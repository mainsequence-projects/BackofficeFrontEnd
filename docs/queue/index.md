# Cases

Use the review queue to find work and open a case's evidence, findings and staff responsibility together. Loans, account opening and document review share this workspace. Each case has a business type and an exact Document Set version.

## Open this page

Choose **Cases** in Back Office, then select a subject's name in the queue. You can also choose **Open review workspace** on a subject's case under **Requirements**.

## What you can do

Search subjects, filter by case type or reviewer responsibility, inspect cited source pages, compare retained reader values, review document revisions, run checks, and print the last retained report.

## Common tasks

Choose **New case**, select its **Case subject**, then a **Case type** such as
**New loan** or **Account opening**. Select a permitted **Document Set version**
and choose **Create case**. Changing the type clears the previous version choice.
You can create the case before uploading evidence. Existing cases keep their
selected version when new Document Set versions are published.

1. Select **Assigned to me**, **Unassigned**, or **All accessible cases** and a case type. Search by the subject's name or reference.
2. Open a case. Its subject appears at the top; the **Assigned reviewers** section lists staff separately.
3. As an authorized reviewer, choose **Assign to me** to take responsibility. Several reviewers can join the same case independently. **Leave case** removes only your own responsibility.
4. Select a linked document or **Inspect page** on a finding to read its source alongside reader values and the policy result.
5. Enter a **Review reason**, then accept or reject the selected submitted revision. Correct incomplete drafts through **Correct attributes**.
6. Choose **Run checks** to retain a fresh evaluation. When background processing finishes, choose **View evaluation**.
7. Open **Control report** and use **Print / save PDF** to export the retained findings.

## Understand what you see

A **subject** is the person whose information appears in the documents. A **reviewer** is a staff user responsible for checking the case. Taking responsibility does not grant access or approve evidence. Only authorized staff can record review decisions.

The accessible-case total reflects your search and responsibility filters. State cards, distribution and frequent top findings count only the current page. Page filters do not search other pages. **Checks satisfied** describes evidence requirements; it does not approve a loan or account.

The workspace shows current requirements. Outdated retained comparisons are marked and excluded from current findings. **Subject activity** includes changes across that subject's cases. The printable report retains the evaluation's original findings and is not a signed protocol.

## If something goes wrong

Reload a case if another reviewer has changed it. If the source checksum does not match its citation, inspect the original evidence before proceeding. Use **Run checks** when a retained evaluation is out of date. If processing fails, use its retry control; if the evidence changed during processing, start a fresh evaluation.

If no cases appear, check the search and filters or choose **New case**. You can also create a case on the subject's **Requirements** page. Staff membership never bypasses access restrictions.
